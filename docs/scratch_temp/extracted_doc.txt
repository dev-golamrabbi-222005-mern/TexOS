 TexOS RMG Worker Safety &amp; Digital Production Tracking Platform Project Overview &amp; Build Documentation Architecture foundation reused from the LAUNDRIX project Prepared for: NITER Innovate Hackathon 2026 — RMG Industry Track August 2026 Project Overview TexOS is a digital platform designed to solve two connected, real problems in Bangladesh's Ready-Made Garments (RMG) industry: (1) workers have no safe, trackable way to report safety hazards or grievances, and (2) factories track production (cutting → sewing → QC → packing) manually, with no real-time visibility into where a batch of garments currently is or whether it passed quality checks. Instead of building two disconnected tools, TexOS unifies both under one role-based platform: workers and line supervisors interact with the same bundle/QR system that quality inspectors use for compliance checks, and the same platform lets any worker anonymously raise a grievance that HR can track to resolution — all inside one factory-operations dashboard. The system deliberately reuses the architecture, data-modeling patterns, and workflow logic already designed and validated in the LAUNDRIX project (a Multi-Branch &amp; Multi-Vendor Laundry Management Platform), because LAUNDRIX already solved the same core technical problem: tracking a physical item through a multi-stage process using QR/barcode scans, batching items together, running quality inspection on them, and giving different roles different dashboards over the same data. Mission To give every RMG worker a safe channel to be heard, and every factory floor a simple digital system to know exactly where production stands — without requiring expensive hardware or enterprise software budgets. Vision To become the standard lightweight operations layer for small-and-mid-sized RMG factories in Bangladesh — starting with worker safety and bundle tracking, and expanding toward the fuller LAUNDRIX-style operational suite (inventory, buyer portals, multi-factory analytics) as the product matures. Business Model (Post-Hackathon) Per-factory monthly subscription (tiered by number of active workers/lines). Free tier for a single production line, to let small factories try it risk-free. Optional paid add-on: compliance report exports formatted for buyer audits (BSCI/WRAP-style documentation). Business Logic A ProductionOrder is broken into multiple Bundles at the cutting stage; each Bundle gets one printed QR label. A Line Supervisor scans a Bundle's QR with a phone camera every time it moves to a new stage (Cutting → Sewing → QC → Packing). Every scan writes one row to BundleScanHistory — this is your full audit trail / traceability record. The WIP (Work-In-Progress) dashboard reads WIPSnapshot (or aggregates BundleScanHistory live for small data volumes) to show how many bundles are at each stage right now. What to Keep As-Is (copy from LAUNDRIX) GarmentScanHistory → BundleScanHistory : identical field shape and purpose, just one level up in granularity. What to Change (rename / re-scope) GarmentItem (per-piece tracking) → Bundle (per-batch-of-pieces tracking) — this is a genuine granularity redesign, not a rename. Do not build per-piece tracking; it is unrealistic for a 7-day build and not how real factories operate. What to Build New (not in LAUNDRIX) Mobile-camera QR scan UI/UX — LAUNDRIX's schema assumes scanning happens, but you must build the actual camera-scan React flow from scratch (a QR scanning library + a simple 'select stage → scan → confirm' screen). WIPSnapshot — a new aggregation entity to keep the live dashboard fast without querying the full scan history every time. Part Summary: Budget 2 full days here — this module has the least direct code reuse and the most new UX (camera permissions, scan reliability testing on real phones). If time runs short anywhere, this is the module to simplify first (e.g., drop WIPSnapshot and just query BundleScanHistory directly for the MVP).
